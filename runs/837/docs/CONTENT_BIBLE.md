# 研究生语境梗库与内容写作规则

## 目标

让玩家感到“这事我真见过/听过”，而不是看到一串脱离情境的网络热词。每条内容都必须回答三件事：它发生在什么科研节点？玩家能做什么？选择会让谁承担后果？

V2 强调“图像 UI + 随机事件”。文字要比 V1 更短，但事件仍然要有情境、选择和后果。

## 已纳入的语境

| 场景 | 共鸣点 | 游戏化落点 |
| --- | --- | --- |
| 招生面试 | 简历很强、方向匹配、隐藏雷点 | 候选人可见维度与隐藏特质 |
| 学院任务 | 学院 KPI、阶段检查、课题组建设 | 一局内短期目标与奖励 |
| 年度考核 | 年终总结、学院评价、资源申请、整改压力 | 换年事件、评分档案、路线选择和结局条件 |
| 课题线 | 具体研究问题、项目方向、论文题目 | 负责人、进度、完成奖励和风险 |
| 投稿 | 工作坊、核心、顶刊、返修、拒稿 | 稿件、投稿档位、录用/返修/拒稿 |
| 同门协作 | 互相讲题、分工、贡献争议 | 协作推进、互相成长、冲突事件 |
| 校友 | 毕业后联系、推荐学生、合作机会 | 校友档案、回响事件、长期关系 |
| 组会 | 大 PPT、被问关键图、下周继续 | 论文进度、压力、能力成长 |
| 抽查 | 摸鱼、卡 bug、卡实验、假装忙 | 状态事件、信任与压力变化 |
| 论文 | With Editor、外审、大修、这真是最后一版了 | 论文进度、学生贡献、审稿事件 |
| 署名 | 一作、通讯、贡献不透明 | 信任、风险、学生反噬 |
| 经费/项目 | 青年基金、横向项目、验收 | 经费、行政压力、学生劳动 |
| 设备/规则 | 白板、工位、补助、毕业线、署名制度 | 长期效率、压力、风险与反噬 |
| 设备/实验 | 仪器报错、预约抢位、数据丢失 | 资源消耗、协作与复现 |
| 毕业 | 延毕焦虑、离组、毕业照 | 学生结局与长期关系 |
| 反馈机制 | 匿名墙、联名邮件、换组 | 课题组瓦解或修复路线 |

## 隐藏特质写法

隐藏特质不是抽卡稀有度，而是叙事和机制钩子。

- **摸鱼雷达**：适合抽查事件，不能只写成“懒”，要给出逃避任务或任务设计不清的可能性。
- **ddl 爆发型**：短期爆发很爽，但不能鼓励长期透支。
- **玻璃心天才**：能力高但压力敏感，适合温和指导和组会翻车。
- **社交悍匪**：会议、人脉、合作事件收益更高。
- **复现洁癖**：进度慢但能降低风险。
- **论文缝合怪**：短期论文快，长期伦理风险高。
- **正义雷达**：对署名、补助和规则敏感，公平路线收益高，压榨路线反噬更强。
- **夜行动物**：深夜冲刺收益高，但压力积累也快。

## 学院任务写法

- 任务文案要像游戏目标，不要写成行政通知全文。
- 奖励要解释为“学院资源”“口碑回流”“制度改善”等合理反馈。
- 任务只引导系统体验，不强迫道德路线；坏导师路线仍然可玩但会付代价。
- 任务目标要覆盖不同系统：招生、学生、设备、规则、论文、项目、毕业、风险修复。

## 年度考核写法

- 年度考核要像一个节点事件，不要写成长篇述职报告。
- 评价必须同时看成果和代价：论文、项目、毕业、信任、学生压力、行政压力和伦理风险都应参与。
- 优秀不等于无脑奖励，可以带来资源，也会带来更多行政关注。
- 预警和危机不只扣分，要给玩家选择：修复学生状态、申请资源，或继续硬冲 KPI。
- 考核后续事件要继续服务路线分歧：低分督导旁听适合修复/遮掩选择，高分经验分享适合制度化/模板化选择。
- KPI 路线可以荒诞，但必须让压力、风险或信任承担后果。

## 课题线写法

- 课题名称要像一个真的研究方向，不能只写“做论文”“发文章”。
- 每条课题都应有取舍：难度、收益、风险、适合的学生类型或设备。
- 课题事件要围绕研究问题推进：假设失败、数据挖掘、边界收缩、补实验，而不是泛泛发生“随机好事”。
- 高风险课题可以来钱快或推进快，但要留下伦理风险、署名争议或学生压力。

## 投稿写法

- 投稿不是“点一下就发表”，要体现不确定性：录用、返修、拒稿都可能发生。
- 返修不是失败，要能回流为论文进度、写作能力或学生成长。
- 拒稿可以有挫败，但不能只惩罚；评审意见也能成为下一轮素材。
- 快速通道和灰色选择必须有明显伦理风险，不能比正常投稿更像无脑最优解。

## 同门协作写法

- 协作不是“两个学生加速器”，要体现分工、互相解释和贡献边界。
- 正向协作可以让学生互相成长，负向协作要留下压力、信任或署名风险。
- 冲突不要写成学生单纯不懂事，要落到任务不清、规则不明、贡献不透明。
- 导师可以通过拆分任务和明确贡献边界修复协作，而不是只讲大道理。

## 校友写法

- 校友不是资源矿，要保留“毕业后的关系感”：有人合作，有人推荐，也有人只是回来讲真话。
- 校友回响要和在读期间的培养质量相关，不能无条件给奖励。
- 真诚反馈可以带来制度修复，坏导师路线则可能只有礼貌和距离感。
- 推荐学生、横向合作、学术合作要写成具体回声，而不是凭空掉资源。

## 地狱梗边界

可以写荒诞，不能把伤害包装成无脑爽点。

1. **先有科研节点，再有梗。** 抢一作只出现在署名、投稿、成果分配节点。
2. **坏选择必须有代价。** 信任下降、压力上升、风险上升、事件反噬至少出现一项。
3. **不要指向真人真校。** 所有学校、学生、导师和事件都必须虚构。
4. **不要复刻具体网帖。** 可以使用广泛语境和改写结构，不搬运具体发言。
5. **好选择也要有趣。** 认真指导、贡献透明、支持毕业不应该只是“道德但无聊”的选项。
6. **讽刺对象是系统荒诞。** 不把学生的困境写成单纯笑料。

## 设备与规则写法

- 设备必须改变真实玩法：效率、压力、风险、学生上限或事件触发。
- 规则必须有持续后果：补助、署名和毕业要求会影响每学期结算，不只是一句介绍。
- 制度梗不能写成抽象口号，要落到具体场景：补助够不够吃饭、贡献表是否透明、毕业线是否被反复后移。
- 设备事件可以荒诞，但要有科研节点，例如数据恢复、设备报错、会议设备翻车、工位不够。

## 事件接口规则

新事件应遵循 `termEvents` 的对象接口：

- `id`：稳定事件标识。
- `kicker`：短场景标签。
- `title`：短标题。
- `body(target)`：事件正文，可绑定目标学生。
- `when(state)`：可选触发条件。
- `target(state)`：可选目标学生选择器。
- `choices`：选择列表，每个选择通过 `effect(target)` 改变至少一项状态。

每个选项必须改变至少一项可见状态，或揭示隐藏特质、推进毕业、触发结局等明确反馈。

## 视觉写作规则

- 事件正文尽量短，把状态变化交给学生气泡、数值、标签和日志。
- 按钮文案要像游戏操作，不要像长篇小说选项。
- 学生状态优先使用短标签：摸鱼、要炸、爆发、补图、卡住、恢复中。
- 日志保留荒诞语气，但不要堆满屏长段落。
